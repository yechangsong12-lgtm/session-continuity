# 会话分工与交接

[English](../SKILL.md) · 简体中文

使用用户指定的语言；没有明确指定时，跟随当前对话的语言。将选定的语言和所有仍有效的要求传给接手方。交接摘要、接手确认及适用的归档询问都使用该语言。需要时可用中英双语交付；路径、标识符和验证数据保持原样。

用主对话保存用户目标、约束、取舍和验收结论。让中间检索、长日志和逐行数据留在执行它们的子任务，主对话根据可回查的证据继续工作。先判断宿主是否支持独立上下文、选模型、读取用量和创建对话。下面的分工和交接方法可由支持 Markdown 指令的助手采用。

## 什么时候拆任务

| 当前需要 | 做法 |
| --- | --- |
| 批量清洗数据、简单联网检索、读长日志，或按明确标准独立核对一批材料 | 交给有独立上下文的低成本子代理。传目标、输入位置、范围、验收条件和必要背景。 |
| “继续”、修一张图片，或对同一份交付物做小改 | 在主对话继续。 |
| 想试另一条路线，两个方案都依赖此前讨论 | 说明要比较的路线，先询问是否开分支以及使用哪个可用模型，获同意后再创建。 |
| 已切换到无关目标，或某项旁支需要用户独立查看、追加指示、长期跟进 | 先询问是否开独立对话及模型选择，可用当前模型、指定可用模型或由 Agent 选择；说明仅本次、今后固定或自动选择。获同意后再创建，只带相关背景。普通旁支接手后主对话继续，整个过程无需询问归档主对话。 |
| 主对话达到有效上下文窗口的 80% | 已启用自动保存且整项主任务仍需迁移时，先自动保存，读出原对话实际模型，用一个问题确认本次是否沿用它开接续，再创建并核实接手。归档询问须满足下文的整体迁移条件。其余情况按用户选择提醒或存档进度。 |

这些条件参考 Claude Code 的子代理、分支和会话管理建议。80% 是本流程采用的提醒阈值。各宿主的创建、恢复与压缩命令按本机版本选择。[Claude Code 子代理](https://code.claude.com/docs/en/sub-agents) · [会话管理](https://code.claude.com/docs/en/sessions) · [最佳实践](https://code.claude.com/docs/en/best-practices) · [命令参考](https://code.claude.com/docs/en/commands)

## 选模型与接收结果

- 用户已为本次任务指定模型时按本次选择执行。用户明确表示“总是用某模型”时按所选范围记下该偏好；临时指定只适用本次。本机可用模型清单在执行时核对。
- 没有既定偏好且选择有实际影响时，可询问“这次用哪个模型、以后固定用哪个，还是由我按任务和成本选择？”给出宿主实际可用的选项。用户选择自动，或普通任务无需打断时，在具备所需工具、上下文和准确度的模型中优先选 token 成本低的。价格未知时用宿主标示的经济档作依据，并按需要说明判断依据。固定模型不可用时说明并给可用替代，让用户决定是否更换固定偏好。
- Sol 是可选项。其他助手可选各自可用的低成本模型。不能单独选择模型或启动代理时，说明实际执行方式，采用定向检索、文件整理和简短回报。
- 给子代理划清任务和可写的文件范围。一次性检索优先让它在干净上下文中工作。完成后只交回**关键结论、来源、明细文件位置**，有缺口或冲突时一并说明。来源可用原始链接、数据日期或本地表的工作表及行范围。简短检索可直接引用来源，已有明细时复用原文件。
- 主对话回查影响决定的数字、冲突来源和关键样本，再结合用户约束决策。批量整理和简单检索可按任务描述直接选用本技能，后台子代理将摘要交回主对话。需要单独跟进的旁支先建议开独立聊天。

## 普通旁支结束后

先把子对话的结论、来源和明细文件位置交回主对话。只有主任务与旁支均完成后，才考虑整理该**子对话**。确认没有待办、待审或只保存在子对话里的证据，也没有用户要求保留。具备这些条件且用户授权自动整理时，可以归档该子对话；具备条件但缺少自动整理授权时，询问是否归档这个具体子对话。仍有未结事项时保留子对话。普通旁支的创建、接手或完成都不会触发归档主对话的询问。

## 上下文达到 80% 时

按实际运行环境选择[DeepSeek Harness](deepseek-harness.md)、[腾讯 WorkBuddy](workbuddy.md) 或 [Claude 桌面版的 Chat、Cowork 和 Code](claude-desktop.md) 指南。在 Codex 以外运行存档脚本时，用 `--source` 标出实际来源，例如 `--source workbuddy`。使用该助手当前任务的模型与用量证据。两个环境的路径不同时，可用 `bootstrap.py --root WORKSPACE --portable` 导出包含结论、证据位置和待办的交接文本。用户写入摘要的路径和来源会随文本保留；通过用户认可的位置提供接手方需要的证据文件。

调整 Codex 默认窗口、安装 Codex 事件提醒或给 Claude Code 状态栏添加 80% 提示时，读 [上下文配置与提醒](context-settings.md)。只改用户指定的设置。窗口长度、有效窗口和自动压缩阈值分别核验。

用户可为自己启用“达到 80% 自动保存现场”。Codex 本机将这项偏好保存在 `$CODEX_HOME/hooks/session-continuity.json` 的 `{"auto_checkpoint_at_80": true}`。该用户主动开启后，达到阈值可先自动保存并校验现场。整项迁移时读取原对话正在使用的实际模型 X，用一句话询问“要沿用原对话的 X 模型开接续对话吗？也可换模型。”用户同意沿用即已选好模型，明确同意本次开聊后再创建。“继续”仍在原对话执行。后台子代理的经济模型偏好单独适用。新安装默认提醒，是否自动保存及是否开新对话由使用者选择。一般旁支、归档和删除各有独立的授权范围。

实际用量样本达到或超过 80% 后，在下一个可执行事件按偏好保存现场。事件经压缩后延迟送达时，核对当前来源会话与压缩前对应的达标采样，并复查当前占用。若压缩已腾出充足空间，先保留原对话、重新判断是否需要迁移。模拟样本只用于指定的临时测试对话。

1. **保存现状。** 来源对话作为唯一交接发起者。先查同一来源对话的交接请求和回执；同一次交接已有接收对话或待就绪 ID 时从那一步继续。按下文写交接包并校验，记录工作区、来源对话 ID、修订号、未完成事项和第一个可执行动作。任务若已完成就交接完成状态。
2. **创建接续对话。** 在同一工作区准备与该修订匹配的启动提示。按下文把请求中的 `approved_model` 显式传给创建工具。记录宿主返回的 ID，并核实新对话实际使用的模型。模型缺失、不可用、与批准值不符或无法核实时，保留主对话并询问用户。后续新消息沿用这个接续对话。创建结果不明时，先从宿主和回执核实已有对话。接手期间由新对话执行交接范围内的工作，来源对话负责观察接手结果。
3. **核实接手。** 新对话首轮校验对应的交接包，阅读摘要并复查第一步所需的证据，在用户可见的进度中简短说明“已接手修订 N，已核对……，正在……”并继续执行；任务已完成或受阻时报告已核实的结果或阻塞原因。来源对话用 `wait_threads` 等宿主观察接口读取目标对话状态，必要时读取其最近一条实际回复。接手确认须与目标 ID、修订和任务相符。已创建但仍在准备、校验失败或尚无接手证据时，保留来源对话，继续核实或报告具体阻塞。
4. **核实整体迁移后再询问归档。** 询问前再次测量真实来源占用并核对原对话是否还有工作。若压缩后占用已回落或仍有独立待办，保留原对话。确认真实来源仍达到 80%、整个主任务已经移交、新对话已经确认接手三项条件后，在来源对话给出新对话入口及接手进度，然后问一次“新对话已接手，是否归档这个原对话？”仅当用户明确同意归档该来源对话时，对其具体 ID 执行归档。用户选择保留或尚未答复时，让原对话保持可见。重复的高水位事件复用已有交接和归档询问。用户另有明确归档指示时按其指定的对话执行。普通旁支保持主对话活跃。测试仅在用户指定的临时原对话范围内演练归档询问，真实业务对话保持活跃。

使用其他宿主时，优先读取它的用量仪表或事件。仅有状态栏时，越线只产生可见提示，需在下一次可执行的交互中处理。缺少可靠用量时，用标明为“阶段性”的进度保存建议。缺少开新对话的能力时，交付已校验的摘要与启动提示；原对话保留，询问归档前仍需满足上述整体迁移条件。

## 写一份接手后能开工的交接

交接前回读用户最新修正和原始证据。只写接手者执行下一步所需的内容，省略工具调用流水账。按任务实际情况填写：

1. **目标与完成条件**。写当前要交什么、交到哪里、什么结果算完成。保留用户修正后的约束、授权范围、中途追加且仍有效的要求，以及仍需用户决定的事项。
2. **进度与决定**。列出已完成且验证过的工作、正在执行的任务和待做项。对影响后续工作的决定写明原因及依据，清楚区分观察、推断和用户批准。
3. **证据与产物**。附关键来源、日期、明细文件和定位信息。对改动写可复核的测试结果。运行中的任务写任务 ID、现状和安全的下次检查动作。省略凭据、会话全文、访问令牌及带授权参数的链接。
4. **缺口与下一步**。交代仍未解决的问题、已试过且影响下一步的路径。给接手者一个可立即执行的动作，写清在哪执行、预期看到什么。
5. **接手验证**。从新会话视角按交接重找核心文件与依据，确认第一步可执行。核验失败时标出具体缺项；文件完整性测试、业务验收及用户批准分别记录。

## 保存、恢复与开新对话

- 在实际工作区运行脚本。先读已有的 `.agent/continuity/current.yml`、`handoff.md` 和清单。多个独立目标共用工作区时，用 `--target` 配唯一且可读的英文或数字短名，中文全称写入摘要。写下一版时整合仍有效的决定、待办、阻塞、证据指针和复核状态。
- 用 [checkpoint.py](../scripts/checkpoint.py) 的 `--latest-user-request`、`--active-goal` 记目标，用 `--source` 标明决定的实际来源（例如 `claude`、`user`），以可重复的 `--decision`、`--context-file`、`--changed-file`、`--blocked-item` 和 `--open-task` 记交接要素。各项依据不同就把具体来源附在该项决定内；`--evidence` 用于共同证据。脚本从 `--root` 指定的工作区生成版本、摘要和清单。已有项目约定交付位置时，只在内部工作目录保存交接。
- 用 [validate.py](../scripts/validate.py) 核对文件、哈希、脱敏状态与写锁。使用同一个 `--root` 和可选 `--target`。校验通过，再读 `handoff.md` 和 [bootstrap.py](../scripts/bootstrap.py) 输出的接续提示。清单覆盖交接包自身。接手时回到所引源文件或网页复核关键数值和外部状态，然后执行第一项待办。
- 在 Codex 中做 80% 整项迁移时，先用只读命令 `bootstrap.py --show-source-model --thread-id UUID` 查原对话实际模型。UUID 替换为真实来源对话 ID，后续命令沿用同一工作区与目标。等用户明确同意本次开聊，再用 `bootstrap.py --prepare-thread --inherit-source-model --expected-source-model MODEL_SHOWN --thread-id UUID` 准备请求；用户改选模型时增加 `--approved-model OVERRIDE`。核实请求的 `approved_model` 与用户本次批准的一致，在 `create_thread` 调用中显式传入该值作为 `model`。原模型未查到、确认后发生变化或不可用时，保留主对话并询问。普通旁支在同一问题里确认是否开聊和选择模型，获同意后用 `bootstrap.py --prepare-thread --approved-model MODEL_ID` 并传入已批准的模型。用校验过的提示启动同一工作区的新对话。告知接收方按“核实接手”在自身对话报告结果。宿主实际返回 ID 后，用 [thread_receipt.py](../scripts/thread_receipt.py) 的 `--created-thread-id` 记录；仍在准备工作树时用 `--pending-worktree-id`。只有准备文件时，报告“交接已准备”。回执用于定位接收方，实际接手以接收方核验结果为准。 准备命令报错时留在原对话。以前生成的请求和回执只供核对先前操作。 将 MODEL_SHOWN 替换为刚才向用户展示的原模型 ID；若模型发生变化，命令会停止并要求重新确认。
- 在支持 Python 的其他宿主，通用交接脚本也可使用。将启动提示中的 Codex 专属入口替换为当前宿主可用的命令或文件路径。没有本地脚本执行能力时，直接用上面的交接格式输出一段可复制的交接。

例如在已安装 Python 3.11+ 的环境中，从技能目录执行下面的命令。将工作区、实际证据和待办替换为本次任务的内容。Windows 可使用已验证可用的 Python 解释器执行相同的参数。

```text
python scripts/checkpoint.py --root "/path/to/work" --latest-user-request "核对价格表并标出待查项" --active-goal "交付核对后的价格表" --decision "已核对 A2:A30，依据为工作区内的原始报价表" --context-file "原始报价表.csv" --open-task "打开报价表第 31 行，与供应商报价核对币种"
python scripts/validate.py --root "/path/to/work"
python scripts/bootstrap.py --root "/path/to/work"
```

需要评估长日志、长循环等压力信号时使用 [guard.py](../scripts/guard.py)。它的综合判断适合安排阶段存档，80% 提醒以宿主采样为准。已安装 Bash 快捷命令时可沿用 `sc save`、`sc v`、`sc h` 等。三方复核使用[三方交接约定](triparty.md)，核对失败时查[故障处理](failure-modes.md)，文件结构见[交接结构](schema.md)。
